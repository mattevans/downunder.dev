Why BEACON_SYNTHETIC_*

Naming parallels the existing LIBP2P_TRACE_SYNTHETIC_HEARTBEAT precedent — honest about the fact we're synthesising these via CL instrumentation; there's no beacon-API SSE equivalent. Both fire on every TYSM node (every slot / every epoch boundary respectively). Server-side dedup is intentionally not applied: meta_client_name is part of the ClickHouse ORDER BY so each witness keeps its own row. Divergence between nodes is signal (one sees the envelope, another doesn't; different fork-choice timing; per-node settle/drop latency).
