How BALs + ePBS Interact

Under ePBS, the execution payload is delivered separately from the beacon block via SignedExecutionPayloadEnvelope. BALs live inside the execution payload. This means:

BAL data arrives with the envelope, not the block.Cannon derivers must source from envelope.
If builder withholds payload → no BAL for that slot.Block has bid but no execution data.
Execution requests move to envelope.Deposits, withdrawals, consolidations processed during process_execution_payload.
Transactions + withdrawals move to envelope.All cannon derivers extracting from block body must update.

TYSM: Fastest Path to ePBS Events

TYSM is our patched Prysm overlay that hooks into the CL client and forwards events to Xatu. Upstream Prysm already has preliminary Glamsterdam support. We can capture ePBS events directly without waiting for beacon API SSE proposals.
